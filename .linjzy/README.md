# New API 定制

基于 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 的已发布版本维护独立业务补丁。
补丁在 `patches/`，测试在 `tests/`，发布脚本在 `bin/`，服务器部署工具在 `deploy/`。

| 补丁 | 功能 |
| --- | --- |
| `usage-logs-auto-refresh.patch` | 用量日志自动刷新、错误去重，失败后停止刷新 |
| `responses-capacity-retry.patch` | 输出前无计费用量的容量错误重试，保留已产生用量的结算 |
| `astra-iq-gate.patch` | Astra 定时答题检测、模型级路由门禁及卡片历史状态条 |

容量重试需要开启自动重试，并配置同模型、同分组的可用替代渠道。
已产生输出或计费用量的请求不会重放。

## 发布

[GitHub Actions](../.github/workflows/custom-image.yml) 每六小时运行；`.linjzy/` 下非文档改动推送到 `main`，或手动触发时也运行。
流程：取最新上游 release，在其提交上应用补丁，通过后端、前端和镜像启动检查后发布源码分支和镜像。

- 镜像 `ghcr.io/linjzy/new-api:<release>-custom-<build-sha>-<upstream-sha>`，源码分支 `custom/<同名>`；分支不含 `.github/workflows`。
- 构建输入（补丁、prepare 脚本）与验证输入（tests、deploy、verify 脚本）分别计算摘要；镜像和匹配的 `verified-*` 记录已存在时直接复用，改 workflow 或文档不会重建。
- 定时运行或手动 `promote_candidate=true` 才移动 `candidate`，旧 `candidate` 改标为 `previous`；定时运行和后端补丁变更会追加 race 检查。
- 每次成功后只保留 `candidate`、`previous` 和本次镜像及其 `custom/*` 分支，其余 ghcr 版本和分支删除。

补丁失配时构建失败，日志打印 `.rej` 内容。移植：

```bash
git fetch https://github.com/QuantumNous/new-api.git "refs/tags/$TAG" && git worktree add ../port FETCH_HEAD
cp -R .linjzy ../port/ && cd ../port
bash .linjzy/bin/prepare-release.sh . "$TAG" "$(git rev-parse HEAD)" custom/port   # 失败时保留部分应用结果和 .rej
```

修好后重新生成对应补丁并提交到本仓库。Astra 补丁以 rc.40 生产源码为基线；更换上游版本后必须重新验证。
`main` 的其余内容是上游 tag 的快照，只为方便阅读；需要时 `git merge <tag>` 同步。

## 本地验证

```bash
bash .linjzy/bin/verify-release.sh SOURCE all
bash .linjzy/bin/verify-release.sh SOURCE race
python3 -m unittest discover -s .linjzy/tests -p 'test_*.py'
actionlint .github/workflows/custom-image.yml
shellcheck .linjzy/bin/*.sh .linjzy/deploy/bin/*.sh
```

## Astra 智力检测

- 容器环境变量 `ASTRA_IQ_ENABLED=true` 启用；缺省关闭。回滚开关为 `false`，重建应用容器生效，无需删除渠道或数据库结果。
- 仅检测启用且配置了 `gpt-6-astra` 的渠道，手动或自动停用均跳过，默认全天、以每轮开始时间为基准每 5 分钟一轮（调度轮询误差最多 15 秒），最多并行 3 个渠道，每个渠道最长 2 分钟。独立系统任务使用现有数据库租约避免多节点重复执行；上一轮未完成时不会重叠启动。
- 检测由随镜像固定安装的官方 **Codex CLI 0.157.1** 发起，通过 `/v1/responses` 流式调用。官方 GitHub 二进制包经 SHA-256 校验，CI 使用同版本真实客户端回归，镜像启动检查验证其版本。每次检测使用独立临时配置、只读沙箱与单次请求代理；上游密钥仅由网关持有，CLI 使用一次性本地代理令牌，关闭 shell、浏览器、插件等工具。普通模型测试不受影响。
- 使用指定糖果题，标准答案 **21**，请求固定 `medium` 推理强度，覆盖渠道的推理参数替换。题目不携带答案。普通业务请求参数保持原样。
- 多密钥渠道逐一检查当前启用的密钥，全部正确才通过；答错或请求失败立即保存阻断结果。不会改变其他模型或渠道整体开关。
- 渠道标题旁“检测设置”提供启用检测、开始时间、结束时间、间隔（分钟）、失败停用，适用于所有 Astra 渠道。每天按北京时间 UTC+8 执行，支持跨午夜；相同时间表示全天，间隔支持 1～1440 分钟。默认检测开启、00:00→00:00、5 分钟、失败停用开启。关闭“启用检测”后不启动新请求，已有失败结果不限制调用，卡片检测条隐藏；历史保留，重新开启恢复显示。旧配置缺少 enabled 字段时默认为开启。设置保存为共享数据库单个 JSON 值，原子更新、重启保留；GET 使用渠道读权限，PUT 使用渠道写权限。
- 无当前检测结果允许调用，包括首次未测、删除最新结果、题目/客户端版本或凭据/上游配置变化。仅在“失败停用”开启且最新适用结果为失败或异常时跳过渠道，复检正确后恢复；关闭开关仍继续检测、保存结果。时段外保留最近判定，不再因固定 10 分钟过期阻断调用；读取设置或结果失败仍拒绝选用，避免把数据库故障误当成没有结果。
- 每个每日时段开始后按下一次调度轮询启动检测；全天时段跨午夜保持既定间隔。结束后不启动新的渠道/密钥检测，在途请求允许完成，尚未完成全部密钥检测的部分结果不会覆盖当前判定。
- 内存路由、数据库路由、重试与会话亲和都检查共享结果。指定渠道不合格时拒绝，不突破其绑定限制；检测完成前已经发出的请求不追溯中止。
- 卡片底部在分组名称后同一行显示最近 24 轮的精细色块，保持原卡片尺寸：绿=通过、红=答错、橙=异常、灰=未测，色块上下无额外文案。点击或键盘激活任意历史色块，可查看当轮题目、答案、模型回复、耗时、首字延迟、Token 用量、HTTP 状态、接口及客户端版本；旧记录未保存的指标留空。前端每 30 秒刷新，路由仍只依据最新有效通过结果。
- 状态条展示最近 24 个检测间隔，以服务器时间及本轮开始时间定位；缺测、暂停和删除造成的空档留白，不将前后结果拼接。旧记录以完成时间减耗时回推开始时间，历史仍最多保存 24 轮。
- 失败详情在题目前显示脱敏后的错误消息、错误码、类型及真实 HTTP 状态，包括 HTTP 200 后流内报错。答题失败显示预期与实际答案。不会保存请求头、密钥、原始错误响应体或完整 CLI 事件，消息最多 2048 字符；旧记录没有错误正文时明确标注未保存。
- 详情支持删除此次结果或清空当前渠道全部检测结果，均需确认并由服务端校验渠道写权限。删除旧记录保留当前判定；删除最新结果或清空后回到未检测状态并允许调用，不把更早的历史记录作为最新判定。历史写入和删除使用事务，避免完成中的检测重新带回已经删除的历史；后续检测可以正常生成新记录。
- 检测结果只写入独立 `astra_iq_results` 表，现有渠道/密钥/计费表结构不变；历史最多保留 24 轮，详情列在 MySQL 使用 LONGTEXT，SQLite/PostgreSQL 使用 TEXT；迁移保留原有历史。切换客户端后视为暂无适用结果，继续由官方客户端生成新的检测记录。默认全天 5 分钟间隔时，每个启用密钥每天约 288 次上游检测请求，会产生上游用量，沿用现有渠道测试日志记录方式。
- 这是一道固定题的质量门禁，不能证明模型身份或等价于通用智商评测。

升级时保持补丁列于 `prepare-release.py` 和 `release-inputs.py`，不要直接使用未打补丁的官方镜像。CI 在真实 SQLite、MySQL 8、PostgreSQL 15 上验证新增表、重复迁移、旧渠道保留、即时跳过/恢复和缓存路径，并运行前端、后端回归与镜像启动检查；失败不会移动 candidate。

部署固定上游版本时手动指定 release，并保留当前镜像 digest、数据库备份及 Compose 配置。独立结果表是增量添加，回滚至旧镜像时可保留。后续移植以补丁接入点为审查范围，不强行忽略冲突或跳过测试。
